# 05: 隔离 SKU 图片事务异常并可靠恢复后续填写

Status: claimed
Type: bug
Priority: P1
Spec: [0.4.17 Code Review 修复规格](../spec.md)
Findings: R6
Acceptance: AC12, AC13

## What to Build

让单张 SKU Image 的交互错误变成可追踪的事务结果，而不是中断整个进程的 traceback。页面恢复安全后，继续其他图片、重量和详情等独立步骤；对结果不确定的上传或提交保持停止自动重试和保存的约束。

## Dependencies

无前置任务，可立即开始。本任务负责自身打开的图片事务界面与错误边界；通用弹窗策略由任务 04 独立负责，因此 04 不是本任务的强制前置。两者在任务 07 集成核验。

## Context and Boundaries

Review 通过异常注入确认，控件查找、点击及取得 iframe 位于错误捕获范围外，可越过调用方导致后续填写中断。

从身份定位到最终清理都属于同一图片事务。页面重绘后按可靠 SKU Identity 重新定位，而不是继续使用旧元素或行号。区分确定失败、成功以及 Indeterminate Upload；不确定的平台副作用不能被伪装成可立即重试的普通失败。

本任务建立任务 06 可复用的事务阶段、错误结果及清理边界，保留现有可用调用方式并同步其消费者。素材正确性修复由 06 完成，不在本任务中另造全套媒体平台。

## Acceptance Criteria

- [ ] AC12：行定位、控件查询、点击、iframe 获取、上传、提交、回读和清理阶段的预期交互异常均被记录，不再以未捕获异常中断整个运行。
- [ ] AC12：失败记录包含受影响 SKU、阶段和原始错误；清理再次失败时保留原始错误及恢复结果。
- [ ] AC12：元素重建后重新依据身份定位；无法可靠定位时停止该事务，不按页面顺序猜测。
- [ ] AC13：确定失败且页面恢复安全的可选图片产生警告，后续独立填写被实际执行；必填图片失败仍阻止保存。
- [ ] AC13：上传或提交结果未知时阻止自动重试及保存，报告待核实状态；页面未安全恢复时也不强行继续。
- [ ] 文件上传框和“添加”选择器路径都在完整边界内，重试与等待均有界，清理仅影响所属事务。
- [ ] 故障注入保留真实事务处理逻辑，并验证后续步骤和保存门禁；不只 mock 整个图片函数返回失败。
- [ ] 相关旧测试通过，完成两轴 Code Review，记录失败到通过证据及任务 06 可依赖的事务结果后再标记 resolved。
