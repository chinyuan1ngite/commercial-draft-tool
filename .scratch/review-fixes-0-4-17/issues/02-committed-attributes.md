# 02: 以已提交选项确认属性并消除重复回显

Status: resolved
Type: bug
Priority: P1
Spec: [0.4.17 Code Review 修复规格](../spec.md)
Findings: R2
Acceptance: AC04, AC05

## What to Build

让属性填写的成功状态反映卖家表单真正接受的值。搜索框内只有文字、尚未选择选项时不能返回成功；已选值在报告中只回读一次，同时保留普通文本、可自定义输入、单选和多选的正确行为。

## Dependencies

无前置任务，可立即开始。通过隔离属性控件验证，不依赖二维 SKU 或图片修复。

## Context and Boundaries

Review 已在本地 Chrome 页面复现：搜索框输入文字后，已提交值仍为空，填写入口却返回 true。现有读取过程把搜索文字作为选中值的后备，新增成功判断因此提前退出。

枚举字段的搜索、选择和提交必须区分；普通文本字段仍读取实际文本值。按控件的已提交节点回读，而不是通过删除重复字符猜测真实值。证书号码是普通文本类型的回归场景，不能把具体证书值或属性样例硬编码进通用逻辑。

## Acceptance Criteria

- [x] AC04：必填可搜索枚举只输入文字、没有选中选项时，填写结果不是成功，必填属性校验仍失败。
- [x] AC05：异步加载的有效选项被明确选择和提交，稳定回读后才报告成功；不存在的选项产生明确失败。
- [x] AC05：普通文本认证字段、自定义文本控件、单选及多选保持正确行为；多选能移除与目标不符的预填项。
- [x] AC05：重复显示容器不造成重复拼接；合法值本身包含重复字符时不被截断或改写。
- [x] 必填失败仍进入现有保存前校验；报告保存的值与实际已提交值一致。
- [x] 使用真实 DOM fixture 检查提交状态、blur 后回读及报告，不以预设的 selected-value 返回值证明提交成功。
- [x] 相关旧测试通过，完成 Standards 与 Spec 两轴 Code Review，记录可重复的失败到通过证据后再标记 resolved。
