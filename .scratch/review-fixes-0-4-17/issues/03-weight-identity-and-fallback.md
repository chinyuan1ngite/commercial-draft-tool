# 03: 按可靠 SKU 身份映射重量并恢复缺重后备值

Status: resolved
Type: bug
Priority: P1
Spec: [0.4.17 Code Review 修复规格](../spec.md)
Findings: R3, R4
Acceptance: AC06, AC07, AC08, AC09, AC17

## What to Build

让每个目标物流行获得所属 SKU 的正确重量，适应规格列和行顺序变化。对身份已经确认但没有采集重量的 SKU，使用显式配置值或 1000g；保留其他 SKU 的真实重量。报告及草稿重开核验采用同一身份语义。

## Dependencies

无前置任务，可立即开始。直接使用包含完整目标物流行的 fixture，不把销售规格生成任务设为本任务的前置条件。

## Context and Boundaries

本任务覆盖两项已复现问题：规格键只拼接值而丢失维度名，可能在列重排后把 100g 和 200g 填反；唯一可识别但缺重量的 SKU 被丢弃身份，导致 300g、500g、缺重的三行全部不填。

先解析所有源 SKU 的身份，再查重量。完整规格身份应包含维度名与值；源 SKU ID、经验证唯一的物流货号别名可以参与定位。货号是物流别名，不替代媒体使用的 canonical SKU Identity。最小范围复用既有身份规范，避免再新增一套按值顺序拼接的规则。

重量优先级为适用的源重量、有效显式后备值、1000g。仅在源证据表明是产品级共同重量时才作为统一源重量。若不同 SKU 的重量存在映射歧义，应在写入前阻断，不能用全表默认值掩盖错配。

## Acceptance Criteria

- [x] AC06：源 A=(first:x, second:y)、B=(first:y, second:x)，目标列反转、行重排或源字典顺序变化时，A 仍为 100g、B 仍为 200g。
- [x] AC07：三个唯一规格的源重量为 300g、500g、缺失时，目标为 300g、500g、1000g；显式后备值设为 1500g 时只改变缺重行。
- [x] AC08：全部缺重时可统一使用配置值或 1000g；存在已证明的产品共同重量时使用源重量，不虚构逐 SKU 身份。
- [x] AC09：重复或未验证货号、规格不完整、身份冲突和差异重量无法映射时，不进行猜测写入，报告歧义并阻止不可靠保存。
- [x] 已有源 SKU ID 和唯一物流货号映射保持可用；缺重 SKU 不因不在重量表中而失去已知身份。
- [x] 目标单位保持 g；保留既有数值有效性约束；报告能区分每行重量来自采集、显式配置还是默认值。
- [x] AC17 的重量部分：草稿重开后按 SKU 身份重新匹配重量；单纯行顺序变化不失败，真正的重量交换必须失败。
- [x] 同步纠正用户说明中“缺失”和“歧义”的区别，避免承诺歧义时统一填默认值。
- [x] 纯身份单测与真实物流 DOM fixture 均覆盖上述情况；相关旧测试通过，完成两轴 Code Review，记录失败到通过证据后再标记 resolved。

## Answer
