## 故障分流

先本地读取完整报告，再分享最小脱敏摘要：

1. 校验失败：看 issues，核对配置和文件。合成负向样例可练习这一步。
2. 详情为 0：比较 requested/inserted/preview_count，读首个 batch 的 stage、error、side_effect_possible。
3. 文字成功：不能据此认定图片或草稿已完成。
4. 上传或保存状态未知：先人工核对页面/草稿箱，不立即重复执行。
5. 页面结构变化：整理最小 DOM 复现，再交给维护者。

使用者故障操作见 [操作说明](操作说明.md)，开发定位见 [架构地图](architecture.md)，反馈要求见 [贡献指南](../CONTRIBUTING.md)。
