# 1688 自动草稿工具操作说明

## 使用边界

工具只负责采集、数据校验、填写卖家页面和保存草稿。正式上架必须由人工进入卖家后台审核后操作。程序内置正式发布拦截，不会代替审核人点击发布。

## 首次使用

1. 双击 `Commercial1688DraftTool.exe`；源码版双击 `launcher.bat`。
2. 确认界面显示“Chrome：已检测”。未检测时先安装 Chrome。
3. 点击“编辑…”，填写店铺与类目配置。
4. 保存配置后，先采集一个测试商品，再执行“数据校验”和“预览填充”。
5. 检查预览页面及输出报告，确认类目、店铺、物流和属性映射正确后，才使用“保存草稿”。

## 配置字段

| 字段 | 填写要求 |
|---|---|
| 叶子类目 ID | 卖家发布页最终叶子类目的数字 ID，不填写类目名称代替 |
| 类目名称 | 便于人工核对的名称 |
| 店铺识别文本 | 卖家发布页稳定显示、能唯一识别当前店铺的文字 |
| 发货地址匹配文本 | 与卖家后台已保存地址一致的稳定片段 |
| 运费模板名称 | 卖家后台已存在的模板名称 |
| 发货承诺 | 页面实际存在的选项，例如 `48小时发货` |
| 包裹重量 | 正整数，单位为克 |
| 卖家 Profile 目录 | 每个卖家店铺必须独立，不要与买家 Profile 共用 |
| 草稿输出目录 | 保存运行报告、截图、台账和运行素材 |

类目属性规则仍保存在 `settings.local.json` 的 `category_rules.by_category.<类目ID>` 中。首次适配新类目时必须先预览并人工确认必填属性，不能通过猜测补值。

## 标准流程

### 1. 采集商品

在“采集链接”输入完整的 1688 商品详情链接，点击“采集商品”。首次运行会打开买家浏览器，登录或验证码由操作者处理。成功后启动器自动选择生成的 `product.json`。

采集只接受页面结构化商品图库。页面没有可信图库、图片下载失败或采集结果不完整时会阻断，需人工处理数据源。

### 2. 数据校验

点击“数据校验”。退出码为 0 才能继续。常见阻断包括：

- 配置字段缺失或只有空格
- 标题过长
- 价格、库存或重量非法
- SKU 维度重复或数据不一致
- 主图或详情图不足
- 素材越过当前商品的 `assets` / `detail-assets` 目录

### 3. 预览填充

点击“预览填充”。程序会打开可见浏览器并填写页面，但不保存草稿。核对：

- 当前店铺身份
- 最终叶子类目
- 标题和主图
- SKU 规格、价格、库存、单品货号
- 必填属性及详情内容
- 发货地址、运费模板、发货承诺和重量

关闭浏览器前可查看页面。默认情况下任务结束会关闭自动化连接；浏览器登录 Profile 会保留。

### 4. 保存草稿

点击“保存草稿”并确认。程序保存后会进入草稿列表，再重新打开本次草稿核验全部关键字段。只有重新核验通过才显示成功。

幂等键为“店铺识别文本 + 源 offer_id”：已有台账时更新原草稿；没有台账但发现同标题历史草稿时会阻断，不会自动删除或覆盖历史草稿。

### 5. 人工审核上架

操作员在卖家后台打开已保存草稿，对照源商品、合规要求和运行报告完成审核。确认无误后由有权限的人员手动正式发布。

## 运行结果

每次执行生成独立目录：

```text
drafts\<offer_id>\<日期时间-随机ID>\
  quality-gate.json
  runtime-config.json
  runtime-product.json
  report.json
  page.html
  page.png
```

退出码：

| 退出码 | 含义 |
|---:|---|
| 0 | 校验或操作完成 |
| 1 | 输入、配置或采集失败 |
| 2 | 需要登录，或采集页面被风控阻断 |
| 3 | 卖家页面关键控件缺失 |
| 4 | 数据质量、安全校验或重新打开核验失败 |
| 5 | 同一卖家 Profile 已被另一个任务占用 |

## 故障处理

- `Chrome：未检测`：安装 Google Chrome 稳定版后重启启动器。
- `login_required`：在打开的浏览器中完成登录，再重新执行任务。
- `blocked_store_identity_mismatch`：停止操作，核对当前卖家账号和店铺识别文本。
- `blocked_existing_same_title_draft`：人工核对历史草稿和本地台账，不要直接改标题绕过。
- `blocked_ledger_draft_not_found`：台账记录与当前店铺不一致，先由管理员核对备份和店铺账号。
- `blocked_profile_in_use`：关闭使用同一卖家 Profile 的其他任务后重试。
- `draft_save_not_verified`：草稿可能已保存但核验未通过；先在后台人工检查，不要立即重复运行。
- 页面结构变化或控件缺失：保留该次 `report.json`、`page.html` 和 `page.png`，停止自动保存并提交维护。

任何情况下都不要删除 `draft-ledger.sqlite3` 来绕过重复草稿保护。
